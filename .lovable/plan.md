# Gotti Stuff — POS для планшета

Кассовое приложение с офлайн-режимом, web-дашбордом для админа, филиалами и уведомлениями по email.

## Технологии

- **Веб-приложение** (TanStack Start) с адаптацией под планшет + **Capacitor** для сборки Android APK
- **Lovable Cloud** (Supabase) — БД, авторизация, RLS
- **Офлайн**: IndexedDB (Dexie) + очередь синхронизации, отправка на сервер при появлении интернета
- **Email**: Resend (через коннектор) — уведомления админу при оплате картой
- **i18n**: русский + узбекский (переключатель)
- Валюта: **UZS**
- Убрана надпись "Lovable" (badge visibility)

## Роли

- **Админ** — первый зарегистрированный. Управляет товарами, филиалами, кассирами, видит отчёты
- **Кассир** — входит по никнейму + PIN-коду (выдаёт админ), привязан к одному филиалу

Используется таблица `user_roles` (enum: `admin`, `cashier`) + функция `has_role` (security definer).

## Структура БД

- `branches` — филиалы (название, адрес)
- `profiles` — пользователи (никнейм, PIN-код-хэш, branch_id, email для админа)
- `user_roles` — роли
- `categories` — категории товаров
- `products` — товары (название, фото, закупочная цена, продающая цена, категория, branch_id либо глобально)
- `stock_movements` — приход/расход (product_id, qty, тип: `income`/`expense`, цена, branch_id, user_id, note)
- `sales` — чеки (branch_id, cashier_id, итог, наличными, картой, сдача, статус, client_uuid для идемпотентности офлайн)
- `sale_items` — позиции чека (product_id, qty, unit_price, cost_price)
- `shifts` — смены кассиров (опционально)

Все таблицы: RLS + GRANT на `authenticated` и `service_role`.

## Экраны приложения (планшет)

**Общие**
- Экран входа: никнейм + PIN (кассир) или email + пароль (админ)
- Меню с боковой панелью (как на референсе): Продажи, Чеки, Товары, Отчёты, Настройки

**Продажи (Касса)**
- Сетка товаров с фото/названием, категории вверху
- Корзина с итогом
- Кнопка «Оплатить» → модалка оплаты:
  - Способ: **Наличные / Карта / Смешанная**
  - Поле «Сумма от клиента» — если меньше итога, кнопка «Оплатить» **заблокирована**; если больше — показывается **сдача**
  - Для смешанной: два поля (наличные + карта), сумма должна ≥ итога
- После оплаты картой или смешанной → триггерится email админу с деталями чека
- Открытые чеки (сохранение незавершённого)

**Товары** (админ)
- Список товаров, добавление/редактирование: название, фото (Supabase Storage), закупочная, продающая, категория
- Категории, модификаторы (опц.), скидки (опц.)

**Приход / Расход** (админ или кассир)
- Приход: выбор товара, кол-во, закупочная цена, продающая цена → обновляет остаток
- Расход: произвольная трата (сумма, описание, категория расхода)

**Отчёты (в приложении, краткие)**
- Приход за период, Расход за период, Прибыль, продажи по способу оплаты
- Фильтр по филиалу (для админа)

## Web-дашборд (Back Office)

Отдельные роуты `/admin/*` под `_authenticated`, доступ только для админа:
- Обзор: сегодняшняя выручка, разбивка нал/карта/смешанная, по филиалам
- Все операции (продажи, приход, расход) с фильтрами
- Графики (Recharts): выручка, прибыль, ТОП товаров
- Управление товарами и категориями
- **Управление филиалами** (создание, редактирование)
- **Управление кассирами**: создание кассира (никнейм + генерация PIN), привязка к филиалу, показ PIN один раз
- Отчёт «по филиалам»: сколько пришло из каждого

## Офлайн-режим

- Каталог товаров, категории, филиал кассира — кэшируются в **IndexedDB (Dexie)**
- Продажи сохраняются локально с `client_uuid` и статусом `pending_sync`
- Индикатор онлайн/офлайн в шапке
- При появлении интернета — фоновая очередь отправляет чеки на сервер (server function, идемпотентность по `client_uuid`)
- Email-уведомление админу отправляется сервером при синхронизации (даже с задержкой)

## Email админу (Resend)

Server function `notifyAdminOfCardPayment` вызывается при оплате картой/смешанной:
- Получатель: email админа (из `profiles` where role=admin)
- Тема: «Оплата картой — [филиал] — [сумма] UZS»
- Тело: список товаров, кол-во, цены, итог, способ оплаты (карта/смешанная с разбивкой), кассир, время

Требуется секрет **RESEND_API_KEY** (запрошу через add_secret после подтверждения плана).

## Прочее

- Убрать placeholder на `/` → редирект на `/pos` (кассир) или `/admin` (админ) или `/login`
- Убрать badge «Lovable» через publish_settings
- Метаданные head: title «Gotti Stuff — POS», description
- Capacitor конфиг (`capacitor.config.ts`, `android/`) для сборки APK — сборка вне preview (инструкция пользователю)
- Обновить `__root.tsx` метаданные

## Технические детали

- Хэш PIN: bcrypt в server function при создании кассира
- Логин кассира: server function принимает никнейм+PIN, проверяет хэш, возвращает magic-link/сессию Supabase (через admin API создаём временную сессию, либо используем email вида `nickname@cashier.gotti.local` + пароль=PIN)
- RLS: кассир видит только свой филиал; админ видит все
- Storage bucket `product-images` (public) для фото товаров

## Этапы реализации

1. Enable Lovable Cloud, миграции БД (все таблицы, RLS, роли, storage bucket)
2. Auth: страница логина (админ email/пароль, кассир никнейм/PIN), роутинг по роли
3. Каталог товаров + категории (админ CRUD, фото)
4. Экран Касса: сетка, корзина, модалка оплаты со сдачей/смешанной
5. Приход/расход
6. Офлайн-слой (Dexie, очередь, синхронизация)
7. Email через Resend (коннектор + server fn)
8. Дашборд админа: обзор, операции, графики, филиалы, кассиры
9. i18n ru/uz, брендинг Gotti Stuff, снятие badge
10. Capacitor: конфиг + инструкция по сборке APK
