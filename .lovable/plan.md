## Проблема

Сейчас APK — это просто WebView, который открывает `https://gotti-stuff-sales-hub.lovable.app`. Без интернета — белый экран. Причина:
- `capacitor.config.ts` содержит `server.url: "https://gotti-stuff-sales-hub.lovable.app"` → Capacitor игнорирует локальные файлы и всегда грузит удалённый сайт.
- В CI workflow копирует пустую папку `www/` в `android/app/src/main/assets/public/` — там только заглушка `index.html`, реальной сборки фронта нет.
- Проект использует TanStack Start (SSR + серверные функции), а не SPA — его нельзя целиком положить в APK как статические файлы без изменений.

## Что сделаю

### 1. Убрать зависимость от удалённого URL
- В `capacitor.config.ts` удалить блок `server.url` → Capacitor будет грузить `file:///android_asset/public/index.html` из APK.
- Оставить `allowMixedContent: false`, `androidScheme: "https"`.

### 2. Собрать настоящий SPA-бандл для APK
Серверные функции (`createServerFn`) внутри APK работать не могут — там нет Node/воркера. Нужен клиентский бандл, который ходит напрямую в Supabase.

- Добавить отдельный Vite-конфиг `vite.config.capacitor.ts` (или режим сборки), который:
  - Собирает чистый React SPA из существующих роутов, минуя TanStack Start SSR/nitro.
  - Точка входа — новый `src/entry-capacitor.tsx` с `createRouter` в режиме `history` и `hydrate: false`.
  - `base: "./"` (для `file://`).
  - Выход — папка `www/` (заменит текущую заглушку).
- Переписать вызовы `createServerFn` так, чтобы клиентский код в Capacitor-бандле шёл прямо в Supabase через `@/integrations/supabase/client` (аутентификация, продажи, смены, товары). Логика уже есть в Dexie/`sync.ts` — расширить: все чтения/записи через Supabase JS SDK, оффлайн-очередь через существующий Dexie.
- Все URL к Supabase — абсолютные (`VITE_SUPABASE_URL` уже такой).

### 3. Оффлайн-режим внутри APK
- При старте — читать кэш из Dexie (`products`, `categories`), показывать сразу.
- При появлении сети — синхронизировать через уже готовый `startAutoSync()` + добавить pull товаров/категорий/смен.
- Авторизация: сохранять сессию Supabase в localStorage (по умолчанию SDK так делает) → повторный вход не нужен.
- Login screen работает оффлайн, если сессия уже сохранена; свежий вход требует сети (нормально).

### 4. Обновить CI (`.github/workflows/android-build.yml`)
- Добавить шаги перед копированием ассетов:
  ```
  npm ci
  npm run build:capacitor   # новый скрипт: vite build --config vite.config.capacitor.ts
  ```
- Копировать `www/*` в `android/app/src/main/assets/public/`.
- Остальное (Gradle, релиз) — без изменений.

### 5. Проверка
- Собрать APK, установить, включить авиарежим, убедиться:
  - Приложение открывается без интернета.
  - Каталог товаров виден (из Dexie).
  - Продажа создаётся и уходит в очередь.
  - При включении сети — синхронизация автоматом.

## Технические детали

- Веб-версия (`https://gotti-stuff-sales-hub.lovable.app`) продолжит работать как сейчас на TanStack Start SSR — второй Vite-конфиг её не ломает.
- Серверные функции остаются для веба; в Capacitor-бандле те же операции идут напрямую в Supabase (RLS уже настроен).
- Роутинг в APK — hash или memory history, чтобы `file://` не ломал глубокие ссылки.
- Размер APK вырастет (весь фронт внутри) — это ожидаемо.
