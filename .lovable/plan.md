## Проблема

Ты не видишь **Assets** на странице Releases — значит релиз ещё не создан. Это может быть по двум причинам:
1. Последняя сборка **упала** (failed), поэтому шаг создания релиза не выполнился.
2. Сборка прошла, но шаг **Publish GitHub Release** упал из-за прав или уже существующего тега.

## Что сделать

### Шаг 1. Ты проверяешь Actions
Открой https://github.com/alexgood11121-create/gotti-stuff-sales-hub/actions и пришли мне скрин последнего запуска (зелёный/красный, какой шаг красный).

### Шаг 2. Я добавляю запасной путь скачивания

Даже без релиза APK всегда доступен как **Artifact** (файл под каждым запуском Actions), но GitHub требует залогиниться, чтобы его скачать. Чтобы APK был доступен по прямой ссылке без логина, я:

- Добавлю в workflow автоматическое удаление старого тега перед созданием нового (чтобы Release пересоздавался и не падал на конфликте).
- Добавлю fallback: если Release не создаётся, публиковать APK через отдельный тег `latest` с постоянной ссылкой.
- Добавлю ручной запуск (**Run workflow** кнопка в Actions), чтобы ты мог пересобрать APK без коммита.

### Шаг 3. Как ты скачаешь после фикса

Постоянная ссылка на APK: `https://github.com/alexgood11121-create/gotti-stuff-sales-hub/releases/download/latest/gotti-stuff-latest.apk`

Открываешь её прямо на планшете в браузере — файл скачается сразу, без входа в GitHub.

## Техническая часть

Изменения в `.github/workflows/android-build.yml`:
- Заменить `tag_name: build-${{ github.run_number }}` + `make_latest: true` на двойную публикацию: версионный тег `build-N` и перезаписываемый тег `latest`.
- Добавить `prerelease: false` и явное удаление старого `latest` тега перед публикацией через `gh release delete latest -y || true`.
- Проверить, что `permissions: contents: write` действительно применяется (уже есть).
